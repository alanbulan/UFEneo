# 招式数据补充格式

每个招式位于 `content/fighters/<id>/moves/<move>.json`，`frames` 的下标是零起始模拟帧，`sprite` 是人物图集相位。脚底坐标原点为 `(0,0)`，x 朝角色前方为正，y 离地向上为正，单位为原生像素。

持续束可在单个 `shots[]` 对象中声明可选 `origin_by_frame`，例如：

```json
{
  "beam": true,
  "spawn": [59, 115],
  "anchor": [59, 115],
  "speed": 0,
  "origin_by_frame": {
    "10": [59, 115],
    "13": [55, 113]
  }
}
```

键必须是本招 `frames` 的有效下标的规范十进制字符串，值必须是两个整数。它按人物**当前模拟帧** `move_tick` 查询，不是按弹体年龄或 sprite 编号查询。`shots` 在源帧消耗时出生，模拟随后推进人物帧，持续束的第一次更新会读取推进后的帧。没有列出的帧使用该束自己的 `anchor`；有此字段的束不读取共用 `frames[].beam_origin`。同一帧的两束可独立跟随各自的手，左右朝向只镜像 x。速度、寿命、碰撞框、命中参数照常执行；持续贴身束应声明 `speed: 0`、`vy: 0`。

没有 `origin_by_frame` 的束保持既有 `frames[].beam_origin → shot.anchor` 回退行为，飞行物快照不增加新字段。表现层只读取每束模拟结果 `x/height`，不另算手位。

发射点依据表为逐束跟随增加可选标记：`frame` 仍为含有 `shots` 的源帧，`field` 为 `shots[n].origin_by_frame`，`follow_frame` 是要检查的人物当前帧，`point` 是该帧该手的依据点。统一门逐束比较，最大容差仍为 2 原生像素。

本次未改变回放文件格式。既有格式 5 的内容指纹包含完整模拟招式数据，因此新增此字段的泰罗及变更弹道数值的雷德王会改变各自参与对局的内容指纹。旧指纹由 `UfeReplayRecorder.load_file` 明确拒绝，提示“规则或招式数据已改变，无法播放该回放”；不使用新数据静默播放旧回放。未使用新字段且数据未变的对局保留原指纹和逐 tick 哈希。
