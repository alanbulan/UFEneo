# 架构

core：纯整数、60 tick 确定性模拟，只包含 x 和离地高度。input：设备转 InputFrame。presentation：只读状态、招式、帧并播放整帧图像、特效和声音。ui：菜单和 HUD，以容器布局组合组件。content：规则、角色、招式、招式表。assets：运行时最终资源。

数据流：设备/回放 → InputFrame → 招式表解析 → 独立状态 → 帧数据 → 命中结算 → 状态快照 → 表现。图片不进入模拟指纹。

专属技：`projectile_resolver.gd` 统一读取逐帧 `shots`、`projectile_guard` 和 `counter_shot`。飞行物框随整数位置推进；正面盾框可销毁、反射或吸收，反射保留原招式数据来源并转移攻击归属，吸收记录进入快照，只有实际吸收到才能反击。瞬移坐标只在招式数据的消失帧改变，表现层读取整帧透明度与独立GPT涟漪，不修改模拟。

演出：开场倒计时与回合结束后的表现时钟分别驱动登场、胜负及时间到动画；模拟结束后保持冻结，演出不推进战斗、不进入回放指纹。挑衅仍是普通招式表驱动的独立动作，训练和对局均用防御+投技触发。

投技：`throw_resolver.gd` 在双方推进后统一配对。攻击方逐tick的 `target` 指定被投姿势编号、朝向、手部抓点和释放路径；被投者的独立姿势数据提供腰胯被抓点。抱持时按两点的世界坐标相等计算根点，释放后按整数进度落地；没有按角色体型写配对偏移。靠墙时两人整体平移。被抓后第1–3个真实tick（含停顿）可拆，双方各播拆投并弹开；伤害只在落地冲击帧结算一次。表现层只读取这些结果，F1可看抓点。

当前运行入口为app/scenes/main.tscn。旧骨骼、纵深、废弃UI和整理历史不属于当前仓库；审片驱动集中到tests/review，但仍在正式主游戏中运行。
